Problem statement

Administrative records can become fragmented across separate files. This project demonstrates a single database-backed interface for maintaining fictional patients, doctors, departments, appointments, and billing records with validation and linked history.

Objectives

  • Apply ASP.NET Core MVC, Razor, and dependency injection.
  • Persist related records in MySQL with EF Core migrations.
  • Demonstrate CRUD, server-side validation, search, and pagination.
  • Prevent invalid appointment slots and protect historical records.
  • Demonstrate temporary Session state for non-sensitive filters.

Database design

Department1 ─── manyDoctor
Patient1 ─── manyAppointment
Doctor1 ─── manyAppointment
Patient1 ─── manyBill
Appointment0..1 ─── 1Bill
  • Unique patient, doctor, appointment, and bill codes.
  • Decimal monetary columns with server-side calculations.
  • Restrictive deletes preserve appointment and bill history.
  • Departments are seeded by the initial migration.

Implemented modules

  • Dashboard: database-backed counts and recent appointments.
  • Patients: register, search, view, edit, deactivate.
  • Doctors: directory, department assignment, fee, availability.
  • Departments: CRUD with duplicate and relationship checks.
  • Appointments: book, filter, reschedule, confirm, complete, cancel.
  • Billing: invoice from completed appointment; print and status view.

Appointment duration: 30 minutes. Input/display time zone: Asia/Kolkata; database stores UTC.
